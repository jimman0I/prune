# Prune 4.0 (native)

The Rust rewrite of Prune. The workspace has three crates: `prune-core` (the engine), `prune-app` (the iced window, binary `Prune`) and `prune-cli` (binary `prune-cli`). Build and test from this folder with `cargo build` and `cargo test --workspace`; lint with `cargo clippy --workspace -- -D warnings`; format with `cargo fmt --all` (CI runs `cargo fmt --all -- --check`). Every dependency must carry an allowed open-source licence, checked by `cargo deny check licenses` (install once with `cargo install cargo-deny --locked`); the allow-list lives in `deny.toml`.

UI text lives in `crates/prune-core/locales/<lang>/prune.ftl` and `cleaners.ftl` (Fluent, 40 languages), read through `prune_core::i18n::Catalog`. The files were generated once from the 3.x catalog by `tools/convert-catalog.mjs` and are edited by hand from now on; `locales/needs-review.json` lists the entries whose 3.x function chose its words by a number or flag (mostly plurals) and still need rewriting as Fluent selects.

`Prune --render-screens <dir> [--theme dark|light] [--lang <code>] [--scale <f32>] [--rail expanded|collapsed]` draws all eight screens to PNGs with no window, beside a running Prune. The canvas is the default window's client area at that scale: the 1280x860 DIP outer window less the frame Windows puts around it at that DPI (`AdjustWindowRectExForDpi`), so 1264x821 at 1x and 2534x1649 at 2x on Windows 11. On a display too small for the default the real window is fitted to the work area and is smaller than the render.
