# Prune 3.2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 3.2.1 with Electron 44.11.5 (already on master, 4969adf) and the theme choice saved in settings.json, so that 4.0 can read it from plain files.

**Architecture:** Today the theme choice lives only in the renderer's localStorage (`prune.theme`). The settings.json `theme` key exists but is never written, and always holds its default, `'dark'`. 3.2.1 makes the frontend write the real choice, plus a marker, through the existing settings update path. Language and size units are already authoritative in settings.json, so they need nothing.

**Tech Stack:** existing 3.x: Express backend (`backend/src/services/settings.js`), React (`frontend/src/hooks/useTheme.jsx`), vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-prune-4-native-rust-design.md` ("Calls made while writing this", first bullet).

## Global Constraints

- 3.x is frozen: this release carries no other change.
- No AI attribution in commits. Never write competing tools' names. Release only on the owner's "publish".
- Release notes have one line per bullet (no hard wrap) when copied to GitHub.

## Review Focus

- A stored localStorage choice that is invalid or absent: settings.json must get `'system'`, never `'dark'` by
  accident. Covered in Task 1.
- Settings write failing (backend not ready yet at first paint): the theme must still apply from localStorage,
  and the sync retries on the next change or launch. Covered in Task 1.
